# Subagent reports

`quick` collects activity and resources locally. `analyze` joins attributed
subagent work to the existing semantic labels of user tasks; it does not make
another Judge request for role or model comparisons. No plugin or role-name
registry is needed. Text and HTML reports use the same aggregates.

## Reading the reports

| Scope | Available data |
|---|---|
| User tasks | Existing counts/statuses and resource averages; child sessions never become user tasks. |
| `quick` activity | Unique created agents, working turns, completed/aborted/incomplete turns, nested creations, roles, and observed model/reasoning settings. |
| `quick` role rows | Created agents and working turns; token totals with request records and legacy estimates separated. Status counts and working time remain aggregate totals. |
| `quick` model rows | Attributed token totals and observed execution settings. A working turn can appear under several settings after a model/effort change. |
| `analyze` cohorts | Completed user tasks with follow-up labels, grouped by agent use and task type; sample count and user steering rate. |
| `analyze` role/model rows | User-task outcomes associated with the role/model, parent resource averages, and average agent token/time/tool sums per observed user task. These cohorts overlap. |
| Parent routing | Agent-use comparisons within the same task type and logged parent model/reasoning setting; this is not a difficulty score. |

Created-agent and working-turn windows are independent. An agent created before
the window can receive new work during it; repeated assignments do not create
another agent. Starts are selected within the window and status is observed as
of `--before`. Historical guardian service sessions are excluded.

Only explicit identities establish attribution. Fork-inherited work is excluded
unless child ownership is confirmed. `analyze` also requires a consistent
`root_turn_id` and verified ancestry to a selected user session; it does not
match tasks by nearby timestamps. Missing or conflicting identities are
reported, not guessed. Unknown roles remain unknown and do not form role
comparison cohorts.

Request usage is deduplicated by `response_id` with confirmed ownership.
`token_usage_record` takes priority; `token_count` is a cumulative-counter
fallback when no request records exist and its baseline/deltas are valid. The
sources remain separate when counters disagree or data is incomplete. Input
already includes cached input, output already includes reasoning, and totals
never add these subsets twice. Parent and child token sources are not combined
into a claimed complete task bill; no monetary price is calculated.

Working time is the sum of valid completed-turn `task_complete.duration_ms`
values, not elapsed user-task time. Parallel durations therefore overlap.
Resource averages use tasks with observed values and show known/missing turn
coverage. Partial records provide partial totals. Tool calls require distinct
`call_id`; missing IDs give a lower bound. A model change can prevent trustworthy
attribution of a turn's duration/tools to one model while request-token
attribution remains possible.

## Statistical limits

- Follow-up selection is required to observe steering. Tasks without a next
  labelled message are excluded from these comparisons, not marked successful.
  No steering does not prove success either.
- Ten observations per matched cohort is a display threshold, not a significance
  test. Smaller or unmatched rows remain descriptive; resource coverage can be
  smaller than the overall cohort.
- Actual difficulty is not recorded by the existing labels. Task-type and parent
  routing strata do not establish equivalent difficulty or a causal benefit.
- Multiple roles/models can participate in one task. The task counts once in
  each corresponding cohort; cohort sizes and task outcomes cannot be summed
  or credited to one participant. There is no role-specific success score or
  comparison against absence of each individual role.
- Older formats remain readable and do not change existing user-task statistics,
  but missing role, ownership, root linkage or duration data can leave agent
  comparisons unavailable.

worker and one reviewer; each agent works for 3 seconds in parallel while its
